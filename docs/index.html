CFG and PDA construction

Ambiguous CFG

S → SS | (S) | [S] | {S} | () | [] | {}

For ()()(), concatenation can be grouped as (SS)S or S(SS), so the grammar is ambiguous.

Unambiguous revised CFG

S → BS | B
B → (S) | () | [S] | [] | {S} | {}

The PDA pushes opening brackets and pops only a matching opener. It accepts when the input is consumed and only the bottom marker remains.

Limitation: this checks delimiter nesting only, not complete programming-language syntax or delimiters inside strings/comments.

CFG and PDA construction

Naïve ambiguous grammar

E → E + E | E * E | (E) | id

For id+id*id, the naïve grammar permits both id+(id*id) and (id+id)*id.

Grammar encoding precedence

E → E + T | T
T → T * F | F
F → (E) | id

Left-recursion-free predictive grammar

E  → T E'
E' → + T E' | ε
T  → F T'
T' → * F T' | ε
F  → ( E ) | id

A generic CFG-to-NPDA expands variables using ε-transitions and matches terminals against the input. This interactive parser is a deterministic predictive parser using look-ahead, not a literal simulation of the generic NPDA.

Limitation: this validates token-level syntax; it does not evaluate expressions, resolve identifiers, or perform type checking.

CASE STUDY 03

Palindrome recognition

NPDA midpoint guess

Check strings over {a,b} that read the same forwards and backwards. The empty string is included.

Try abba, aba, or abab.

CFG derivation

A derivation will appear for accepted input.
CFG and PDA strategy

CFG

S → aSa | bSb | a | b | ε

Example derivation for abba:

S ⇒ aSa
  ⇒ abSba
  ⇒ abεba
  ⇒ abba

An NPDA pushes symbols from the first half, nondeterministically guesses the midpoint, then compares and pops symbols from the second half. For odd lengths it consumes one middle symbol during the switch; for even lengths it switches between symbols.

A marked-centre language {wcwᴿ : w ∈ {a,b}*} can be recognised deterministically because the marker c identifies the midpoint.

Implementation note: this browser validator checks the reversal property directly; it is a reference recognizer, not a literal PDA simulator.

CONCEPT SUMMARY

Why CFGs and PDAs?

Balanced brackets

A stack stores arbitrarily nested opening delimiters and checks matching closing delimiters.

Arithmetic expressions

Grammar structure handles nested parentheses and separates operator precedence levels.

Palindromes

An NPDA can guess the midpoint and compare an unbounded first half with the remaining input.

Why finite automata are insufficient

A finite automaton has only finite control. It cannot retain an unbounded nesting history or an arbitrarily long first half for later comparison. A PDA adds a stack, which provides the memory required by these context-free models.
